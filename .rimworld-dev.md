# Remote Doors development settings

Shared workflows are vendored at `.shared/rimworld-dev-skills` and discovered
through `.agents/skills` and `.claude/skills`. `.rimworld-dev.json` selects this
mod's build, output allowlist, disposable reset save, and test mod order. An
ordinary clone includes the shared snapshot; a sibling repository is needed only
to maintain it. To update from a clean checkout:

```sh
sh .shared/rimworld-dev-skills/scripts/update-subtree.sh /path/to/rimworld-dev-skills
```

## Consumer-specific assertions

- Framework/reference pin: net472 / RimWorld 1.6.4871; verify the source project.
- Only `RemoteDoors.dll` belongs in `1.6/Assemblies/`; keep game/Unity/reference
  assemblies out. Preserve the source project's reference isolation.
- No standalone test project is configured. A build alone is not live validation.
- Create `RemoteDoors-Disposable.rws` explicitly under the repository-local
  `.runtime/rimworld-dev-profile/Saves` if absent; do not import a normal save.
- The configured baseline is API-assisted instrumentation, not shipped
  dependencies. The mod itself currently has no Harmony dependency. Verify
  instrumentation is already installed/enabled before use; do not silently
  install it or alter the user's normal mod profile.
- Discover available runnable actions; the mod may expose none itself, so use
  supported vanilla setup actions intentionally. Do not assume settlement
  generation actions or political actions are applicable.
- Validate powered/unpowered door behavior, switch/conduit changes, power loss,
  and save/reload state in the disposable colony. For remote IEDs, verify the
  powered touch-trigger suppression and unpowered arming, plus continued bullet
  vulnerability. For multiplayer checks, use a separately documented mod list
  and verify state on reload/join; restore the instrumentation baseline afterwards.
- Use native autoload/profile and mod-list logs for startup; no custom
  `GAME_LOADED` or procedural-generation marker is assumed for this mod.

All disposable profiles, save copies and logs remain ignored under `.runtime/`.
